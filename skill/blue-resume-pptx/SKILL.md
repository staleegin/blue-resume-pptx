# 单页 PPT 简历生成（蓝色顶栏版式）

用户发来简历素材（旧简历文件、零散文字、按模板填写的内容都可以，中英文均可），最终交付一份**单页 A4 纵向、可编辑的 .pptx**。只出 .pptx，不出 PDF。

## 流程

1. **提取信息**：从用户给的材料里提取信息，对应到下方的数据结构。附件中的 PDF、Word 文件和图片都要读。
2. **问答补全**：把缺失或含糊的信息**一次性**列成问题问用户，问题合在一条消息里。必问项：姓名、求职意向、联系方式。可选项：照片、主色、个人简介、右栏卡片内容、作品集或 GitHub 链接（设计、技术、媒体类岗位优先问）。用户明确说「没有」的就跳过，不要反复追问。
   按岗位补问常见缺口：
   - 医疗、建筑、教师、厨师、健身等岗位：问证书和执照，包括名称、发证机构、取得时间。
   - 销售、商务拓展、金融、运营等岗位：问量化成果，比如金额、增长率、排名。
   - 技术、工程、设计岗位：问技术栈或工具，以及作品链接。
   - 应届生：问成绩或排名、主修课程、奖学金。
3. **匹配分析（用户给了目标岗位或 JD 时才做）**：先在回复里给一段简短分析，包括哪些经历和 JD 对得上、建议的板块和条目顺序、建议换用 JD 里关键词的措辞、明显缺口。如果改写涉及**事实**，比如添加数字或技能，必须先问用户，不能编造。用户确认后再生成。
4. **精简（内容明显超过一页时）**：一页大约能放 450 个英文词或 30 条要点。超过这个量时，先给出精简方案，**用户确认后再删**：
   - 重复的板块要合并，例如 Experience 和 Work History 内容相同。
   - 只保留近 4 段工作，每段保留 3～4 条最有分量的要点，有数字的优先；更早的经历合并成一行。
   - 单条要点不超过两行；整段的描述拆成要点。
   - 个人简介控制在 2～3 句，不要把技能清单塞进简介。
   - 每张技能卡片的标签不超过 20 个。
5. **加粗规则**：
   - 正文里的数据由脚本自动加黑加粗，包括中文量词（90 人、3 项、400 单、3.2 秒）、%、金额（$2.5M、¥3 万）、million、percent、3x。纯数字（型号、编号）、年份「2026 年」、月份「9 月」不会被加粗。
   - 奖项、立项级别、证书、关键成果、条目里的重点短语，由你在 JSON 中用 `**...**` 标出，标出的部分会显示为黑色加粗。每条最多标一处，不要整条都加粗。
6. **生成**：在工作目录写出 `data.json`，然后运行本技能目录下的脚本：`node <技能目录>/scripts/build_resume.js data.json <姓名>简历.pptx`（首次使用先在仓库根目录 `npm install`）。照片放在 `data.json` 同一目录，并在 `photo` 字段里写文件名。
7. **检查**：
   - 看脚本输出的第一行 JSON：
     - `level` 是压缩档位：0 为原始版式，4 为 8 号字。
     - `movedToRight` 列出被自动挪到右栏的板块。
     - `overflowPt>0` 表示仍然超出一页。这时告诉用户超出了大约几行，并建议删减哪几条，**不要自行删除**。
     - 以「提示：」开头的行要转告用户。
   - 运行 `python /mnt/skills/public/pptx/scripts/office/validate.py`，再转成 PDF（用 `scripts/office/soffice.py --headless --convert-to pdf`），然后 `pdftoppm -png -r 100`，查看渲染图，检查文字有没有重叠或越界。LibreOffice 预览中文时用的是替代字体，间距略有出入，属于正常现象；英文预览用的字体和 Arial 字宽一致，预览可信。
8. **交付**：用 SendUserFile 发送 .pptx。说明里写一两句：用了第几档压缩、有没有板块挪到右栏、哪些地方做了加粗。最后提醒用户在 PowerPoint 里「另存为 PDF」后投递，导出的 PDF 中联系方式链接仍然可以点击。

## 版式要点（脚本已处理，了解即可）
- 顶部是主色圆角块：姓名，下面依次是求职意向、带图标的联系方式胶囊（邮箱和网址可点击）、白色分隔线和简介；照片在右上角，裁成圆形。没有照片时保留空位。
  - 姓名、求职意向、分隔线、简介左对齐在 `HEAD_X`（32.5pt），和联系方式胶囊对齐。用户觉得偏左或偏右时，只调这一个常量。
  - 联系方式的文字框和胶囊同高、垂直居中，图标也居中。
- 左栏是可变板块：板块标题前有一个主色短条；条目标题在左、日期右对齐，标题过长会自动换行；副标题、明细行、要点依次排列。
- 右栏是浅色卡片，有两种：
  - 「小标题 + 三个主色点 + 内容」，小项可以带右侧日期；
  - 标签式：只放一串关键词。
- **语言自动识别**：
  - 中文版式：正文用黑体，全部加粗，姓名用微软雅黑。
  - 英文版式：全部用 Arial，正文不加粗，只加粗标题和重点；英文按单词换行。
- 放不下时按顺序处理：
  1. 先把左栏的短板块（教育、证书、荣誉、语言、技能、兴趣等）挪到右栏，用满右栏空间；
  2. 再收紧行距和间距；
  3. 最后把正文字号降到 8.5 号，再降到 8 号。

## data.json 结构

```json
{
  "theme": "2563EB",
  "lang": "zh",
  "name": "姓名",
  "title": "前端开发工程师",
  "titleLabel": "求职意向：",
  "contacts": [
    { "type": "phone", "text": "186xxxx" },
    { "type": "email", "text": "x@qq.com" },
    { "type": "github", "text": "github.com/xxx" },
    { "type": "portfolio", "text": "作品集", "link": "https://example.com/works" },
    { "type": "location", "text": "杭州" }
  ],
  "summary": "一两句个人简介（可省略）",
  "photo": "photo.jpg",
  "autoBold": true,
  "balance": true,
  "left": [
    { "title": "教育经历", "entries": [
      { "name": "学校", "date": "2022.09 - 2026.06", "sub": "专业", "subRight": "本科",
        "details": ["成绩：GPA 3.7/4.0（专业前 10%）", "主修课程：数据结构、操作系统"] }
    ]},
    { "title": "项目经历", "entries": [
      { "name": "项目名", "date": "2024.10 - 2025.03",
        "details": ["技术栈：React、Node.js", "角色：负责人（4 人团队）"],
        "bullets": ["要点，**重点**黑色加粗"] }
    ]},
    { "title": "志愿服务经历", "side": "left", "entries": [
      { "name": "单位", "date": "2025.04", "sub": "志愿者", "text": "不带项目符号的段落" }
    ]},
    { "title": "成就", "entries": [ { "bullets": ["没有标题的纯列表，会紧贴板块标题"] } ] }
  ],
  "right": [
    { "title": "技能", "tags": ["React", "TypeScript", "Excel"] },
    { "title": "证书", "items": [ { "name": "CET-6", "date": "2024.06", "content": "全国大学英语六级 · 562 分" } ] },
    { "title": "核心数据", "items": [ { "name": "留岗率", "content": "56%（团队平均 35%）" } ] }
  ]
}
```
- `lang`：可以省略，脚本会自动识别；中英混排时可以手动指定 `zh` 或 `en`。
- `contacts.type` 可选：phone / email / location / wechat / web / github / linkedin / link / portfolio / birthday / user；填其他值则不显示图标。
  - email，以及 web、github、linkedin、link、portfolio 中形如网址的文本，会自动变成可点击链接。
  - 也可以用 `link` 字段显式指定链接，只接受 http(s)、mailto、tel 开头的地址。
- `entries` 中的 `name`、`date`、`sub`、`subRight`、`details`、`bullets`、`text` 都可以省略。`details` 是一行一条的明细，冒号前的标签会显示为黑色。
- `side`：`"right"` 表示强制放到右栏，`"left"` 表示禁止挪动。`balance: false` 可以关闭自动挪栏。
- 右栏的卡片可以用 `tags`（标签式），也可以用 `items`（小项式）。`items` 中 `content` 用 `\n` 强制换行，`date` 显示在小项右侧。
- 主色 `theme` 是不带 # 的 6 位十六进制颜色。用户说颜色名时自己换算，例如：墨绿 0F766E、深蓝 1E3A8A、酒红 9F1239、紫 6D28D9、橙 EA580C、深灰 334155。用户没指定颜色时不要写 `theme`，用默认蓝色。

## 给用户的填写模板（用户问怎么填时发这个）

```
姓名：
求职意向：
电话：        邮箱：        城市：
作品集 / GitHub 链接（可不填）：
个人简介（一两句，可不填）：
主色（默认蓝色，可不填）：
照片：作为附件发送（可不发）

## 板块名（如 教育经历 / 实习经历 / 项目经历……）
名称 | 时间
副标题 | 右侧信息（如学历，可不填）
成绩：……（「标签：内容」形式的明细行，可写多行，如 主修课程、技术栈、角色）
- 要点（**重点**会加粗）
没有「-」开头的行算普通段落

## 右栏：技能
关键词1、关键词2、关键词3……
## 右栏：证书
名称 | 时间：发证机构 / 分数

（可选）目标岗位 / JD：
```
